## Context

PasteDeck 使用 `NSStatusItem` 提供菜单栏入口，并以 SwiftUI 横向卡片流呈现剪贴板历史。现有交互已具备基本功能，但部分视觉和滚动行为会造成不必要的位移或状态不明确。

## Goals / Non-Goals

### Goals

- 使菜单栏图标与其它系统状态项的视觉重量协调。
- 保持搜索框左边界稳定，减少展开时的界面跳动。
- 让置顶状态在卡片上持续可见，且不只依赖颜色。
- 保持用户当前浏览位置，仅在必要时滚动。

### Non-Goals

- 不改变置顶排序语义。
- 不改变搜索、筛选和卡片选择的数据流。
- 不新增 toast、文字标签或卡片尺寸。
- 不处理列表视图、iCloud 或持久化性能问题。

## Decisions

### 状态栏图标

继续使用 `doc.on.clipboard` SF Symbol，将视觉字号从 16pt 调整为 14pt，并设置按比例缩小。系统 `NSStatusBarButton` 的点击区域和 `PasteDeck` 辅助功能描述保持不变。

### 搜索框

移除基于容器宽度计算居中位置的 `leadingSpacerWidth`。搜索控件成为头部左侧第一个元素，折叠宽度保持 32pt，展开宽度保持 200pt，左边界不动，过滤器和数量向右移动。折叠态使用语义化按钮，并提供 tooltip 与 VoiceOver 标签。

### 置顶反馈

在卡片蓝色标题栏中、时间左侧保留固定宽度图钉槽位。置顶时显示白色 `pin.fill`，取消置顶时槽位保持但图标隐藏，从而避免类型和时间跳动。图钉提供“已置顶”辅助功能标签。正常动态效果下使用短促淡入和轻微缩放；开启减少动态效果时仅改变透明度。

### 卡片滚动

`ScrollViewReader` 在选中项变化时调用不带 anchor 的 `scrollTo(item.id)`。SwiftUI 仅在目标未完整可见时执行必要滚动；已完整可见时保持原位。该规则同时适用于鼠标点击和键盘选择。开启减少动态效果时不包裹滚动动画。

## Alternatives Considered

- `Pinned` 文字标签：识别明确，但占用预览空间并增加视觉噪音。
- 卡片强调色边条和 toast：反馈过强，且会与选中边框竞争。
- 手工测量卡片和视窗坐标：可精确控制滚动，但当前需求可由原生 `scrollTo` 语义满足，额外几何状态没有必要。
- 自定义菜单栏图标：维护深浅色和多分辨率资源的成本高于本次收益。

## Risks / Trade-offs

- 14pt 图标在不同 macOS 版本上的视觉重量可能略有差异；保留 SF Symbol 和系统按钮可降低差异。
- 无 anchor 的 `scrollTo` 具有最小距离显示完整目标的系统语义；仍需实机回归 `LazyHStack`、动画和不同 macOS 版本下的实际呈现。
- 固定图钉槽位会占用少量标题栏宽度，但可以避免置顶切换时内容跳动。

## Verification

- 运行 `swift test`，确保现有模型、存储和 ViewModel 行为无回归。
- 构建并启动应用，比较状态栏图标与相邻系统图标。
- 验证搜索框展开前后左边界位置不变。
- 验证置顶和取消置顶时图钉状态、排序和辅助功能语义一致。
- 分别通过鼠标和键盘选择完整可见、左侧半露和右侧半露卡片，验证滚动距离。
- 开启减少动态效果后，验证置顶图标只淡入且卡片滚动不使用动画。
- 使用 Accessibility Inspector 验证搜索按钮、图钉状态和状态栏描述。
